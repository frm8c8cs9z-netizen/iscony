# 設計メモ: 入力画面を進行表の形にそろえる(UIのリッチ化)

状態: **構想・設計中(未着手)**。2026-10-19〜20 にユーザーと話して整理しました。

## やりたいこと

すべての入力画面を、進行表の画面(日程区分の詳細)と同じ作りにそろえる。

- 上に**タブ**を置く(進行表では日程区分。名簿ではカテゴリ)。
- その下に**操作ボタンの列**を置く(進行表では 配置・移動・削除・他日程へ移動・審判)。
- 必要なら**絞り込み**を置く。
- 本体は**一覧(表)**にする。
- 追加・編集は**モーダル**で行い、別のページに飛ばない。保存したら、その場で一覧に反映する。スマホではモーダルを全画面にする。

### 名簿でのイメージ

```
ケンコーカップ2026 参加者名簿
[男子A] [男子B] [女子A] [女子B]            ← カテゴリのタブ(人数も出す)
[＋ 追加] ...                               ← 操作のボタン列(中身は未定)
[コード・名前・所属で絞り込み]
┌表示順┬コード┬参加者┬所属┬当日変更┐
│ 0   │1A1 │迎林・森本│広島分化Jr…│なし│  ← 行を押すと編集のモーダル
└──────────────────────────────┘
```

今の名簿は、カテゴリ選択 → カテゴリの名簿 → 別ページの追加・編集画面、と3つの画面を行き来している。

## 決まったこと

- **対象:** 選手変更を除く、すべての入力画面。
- **名簿のボタン列に並べるもの:** まだ決めない。最初は「＋追加」だけにして、触ってから決める。
- **今の別ページの追加・編集画面:** 最初は残す。最終的には整理する(消す)。

## 対象画面の洗い出し(案)

| 画面 | 今の形 | そろえたときのイメージ |
|---|---|---|
| カテゴリ管理 | 一覧 → 別ページで追加・編集 | 一覧 + モーダル(タブは不要) |
| 参加者名簿 | カテゴリ選択 → 一覧 → 別ページ | カテゴリのタブ + 一覧 + モーダル |
| Stage管理 | カテゴリごとの別ページ → 別ページで追加・編集・削除 | カテゴリのタブ + Stage一覧 + モーダル |
| リーグ枠編集 | Stageごとの画面。ドラッグ操作が多い | タブ + 今の操作をそのまま中身に |
| トーナメント参加者割当・試合編集 | トーナメント表ごとの画面 | タブ + 今の操作を中身に |
| 進出元設定 | 大会全体で1画面 | カテゴリのタブで分ける |
| トーナメント名称・リーグ名称・表示順・コート表示順 | それぞれ別ページの一括編集 | 各管理画面のモーダルやボタンに吸収できるか検討 |
| 日程区分・コート管理 | 別ページ | 進行表の画面に寄せられるか検討 |
| 大会設定 | 1枚のフォーム | 対象外、または最後 |
| CSV取込(参加者・Stage枠・進行) | ファイル選択 → 確認 → 取込 | 一覧型ではない。各画面のボタン列に入口だけ置く案 |

画面の性格は2種類ある。

- **「一覧 + 追加・編集」型:** カテゴリ・名簿・Stage
- **「操作が中身」型:** リーグ枠編集・トーナメント割当・進出元

どちらにも、共通の枠(タブ・ボタン列・モーダル)をかぶせる。

## 進め方(案)

1. 共通の枠を1回だけ作る。タブ、ボタン列、モーダルをそろえた部品にする。モーダルでは、保存・入力エラーの表示・スマホでの全画面表示を扱う。
2. 名簿で試す。ボタン列は「＋追加」だけにし、行を押すと編集のモーダルが開くようにする。今の別ページは残す。
3. うまくいけば、カテゴリ管理 → Stage管理 → 操作が中身の画面、の順に広げる。

## 決めること

- 名簿のボタン列の中身(追加、CSV取込、並べ替えなど)。
- モーダルの中の入力欄の並び。たとえばPCで、選手1と選手2を横に並べるか。
- モーダルの作り方の決まりごと。
  - 今あるのは、小さな入力ダイアログ2つ(`pair_maintenance.html`)と、大きなモーダル1つ。大きなモーダルは、開いたときに中身を取ってきて、JSONで送る作り(`5b35015`、トーナメント割当)。
  - 入力チェックが多いフォーム(名簿など)では、サーバーが作ったフォームのHTMLをモーダルに入れ、エラーもサーバー側で付けて返す形が素直だと考えている。
