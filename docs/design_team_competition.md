# 設計メモ: 団体戦(星取方式)のチームとメンバー

状態: **構想・設計中(未着手)**。2026-10-19 にユーザーと話して整理しました。近いうちに団体戦の大会はないので、急ぎません。実装は、後日改めてまとめて取りかかります。

## 今の状態

- 星取方式(`Category.scoring_mode = star`)では、試合の勝敗を「何勝何敗か」で入力できる。入力の方法は2つある。
  - まとめ入力: 勝ち数を入れる。テンキーで入力できる。
  - 詳細入力: 対戦ごとに、どちらが勝ったかだけを入れる(`RoundRobinMatchLeg` / `TournamentMatchLeg`)。
- 対戦数は `match_games` を使う。星取方式では1以上の奇数で、過半数を取った方が勝ち。勝敗が決まった後も残りの対戦をすることがあるので、7対戦なら5-2や7-0も正しい結果として扱う。
- **チームを登録する形がない。** 参加者(`Participant`)は「選手1・選手2」の形しかない。
  - 画面の登録では、選手2が必須になっている。
  - CSVでは選手2を空にできるが、その場合 `display_name` が「チーム名・」のように最後に「・」が残る。
- 星取方式で試したカテゴリ(TEST_2026_3 / KENSOTAI2026_7 の「男子個人」)は、個人戦のペアのデータのまま。本番の星取データはない。

## 最終的な構想

| 段階 | 内容 | 目的 |
|---|---|---|
| 1. チームの登録と表示 | チーム名と所属を登録する。リーグ表・トーナメント表・進行表・結果入力・公開ページに、チーム名(+所属)を出す | 団体戦を正しく表す |
| 2. メンバー登録 | チームに所属する選手を登録する | オーダー表やスコアシートに名前を入れる |
| 3. オーダーとスコアシート | 本部がオーダー表を受け取り、対戦ごとに出場するペアを入れる。名前入りのスコアシートを出す | 本部での準備 |
| 4. 当日の選手変更 | 登録選手が当日変わったときに記録し、選手変更リストを表示する | 個人戦の「当日の選手変更」と同じ考え方 |
| 5. 対戦ごとの詳しい結果 | 対戦ごとのゲームスコアと、各ゲームの結果を管理する | 最終形。今ある対戦ごとの明細(勝者だけ)を広げる |

## 決まったこと(段階1)

- **所属:** ひとまず自由に書ける欄を1つ持つ。市・県・地方なども入る。
- **同じ学校から複数チームが出る場合:** チーム名で区別する(例: 「松江工業A」「松江工業B」)。

## 決めること(段階1の前に)

### 大会バックアップとモデル変更の関係(最初に決める)

今の大会バックアップは、作ったときのマイグレーション名(`schema_version`)が今と一致しないと戻せない。段階1以降はモデルの変更が必要なので、変更した時点で、それまでのバックアップはすべて戻せなくなる。次のどちらにするかを決める。

- **A.** 古い形のバックアップでも、形の違いを吸収して戻せるようにする。
- **B.** 形を変えた時点で古いバックアップは戻せないと割り切る。変更の前後で、バックアップを取り直す運用にする。

**決定(2026-10-19): B。** 大会バックアップはまだ本番で使っていないため、モデルを変えた時点で古いバックアップは戻せないと割り切る。変更の前後で、必要ならバックアップを取り直す。本番で使い始めた後に大きなモデル変更をする場合は、Aを改めて検討する。

### 段階1の設計で決めること

- チームを `Participant` で表すか(チーム名の欄を足す、または選手1の欄をチーム名として使う)、別のモデルにするか。
  - 段階2以降で、メンバー・オーダー・当日の選手変更が付くことを前提に選ぶ。
- 星取方式のカテゴリでの、参加者の登録画面とCSVの列。
- 表示の形: 1行(「松江工業A(島根県)」)と2行(チーム名/所属)を、どこでどちらにするか。個人戦の表示モード(`entry_display_mode`)との関係。
- トーナメント表のSVG(片山表示・両山表示)で、名前を2人分書く前提の箇所の扱い。
- 公開ページでの表示。
