# 大会エントリー(構想)

2026-11-27 作成。構想の段階で、作る時期は決めていない。
所有者と当日担当の仕組み(`docs/design_tournament_access.md`)を作るときに、この構想とぶつからないようにする。

## やりたいこと

- 大会の所有者は、自分が管理するホームページなどに要綱を載せる。
- 参加したい人(選手、または監督など)は、iscony の申込ページからその大会にエントリーする。
- 選手本人が申し込むか、監督が申し込むかは、大会ごとに指定する。
- 流れ:
  1. エントリーしたい人が、利用者として登録する。
  2. 登録が済んだら、実際にエントリーする。
  3. 当日の到着受付、選手変更、棄権の登録も、この仕組みから行う。
- エントリーされた選手を、選手名簿に連携させる。

## 方向として決めたこと

- **エントリーする人は、大会ごとに登録する。** 別の大会に申し込むときは、登録し直す。
- **大会ごとの利用者は、その大会の所有者の管理下に置く。** ただし所有者が意識しなくてよい形にする。
  - エントリーする人は、大会の申込ページからメールアドレスなどで自分で登録する。
  - 登録された人は、自動でその大会の利用者になる。所有者が1件ずつ承認しなくてよい。
  - 所有者が普段見るのは申込の内容。利用者の一覧は必要なときだけ開く。
- 運営側のアカウント(所有者・共同管理者)とは別の仕組みにする。

この形にした理由:

- 選手の名前、所属、連絡先などの個人情報が、その大会の中に閉じる。別の大会の主催者からは見えない。
- iscony 全体の会員の仕組み(会員登録、退会、パスワードを忘れたときの対応など)を全体として作り込まずに済む。
- 大会を削除すれば、その大会の利用者の情報も一緒に消える。
- 当日担当と同じ「その大会だけの利用者」という考え方にそろう。

引き換えになること:

- 同じ監督が何度も申し込む場合、そのたびに登録と選手情報の入力が要る。
  - 必要になったら、前回の申込内容を読み込む仕組みで和らげる。たとえば、申込内容をファイルで受け取って次の大会で読み込む形なら、大会をまたいだアカウントを持たずに済む。

## 名簿との連携(案)

- 申込も名簿も iscony の中にあるので、API は要らない。同じデータベースの中で「申込を名簿に取り込む」操作にする。
- 申込と名簿は分けて持つ。
  - 所有者が確認して確定した申込を、名簿(`Participant` = 出場枠)に取り込む。
  - 「CSV取込は初期投入」という今の考え方で、CSV の代わりに申込が入ってくる位置づけ。
  - 申込が名簿を直接書き換えると、抽選後や当日に思わぬ変更が入るため、そうはしない。
- 当日の選手変更や棄権は、参加者側の申請と本部の承認に分ける。
  - 承認されたら、今ある当日の選手変更・棄権の処理で反映する。
  - 到着受付は承認なしで、そのまま記録してよい。

## 関連

- 監督によるチーム単位の申込は、団体戦の構想(`docs/design_team_competition.md`)と同じ土台。設計するときは一緒に考える。

## 気をつけること

- **個人情報:** 参加者が自分で名前や所属、連絡先を入れるため、保存する情報が増える。
  - 未成年の選手が多いので、選手本人ではなく監督や保護者が登録する前提の方が現実的かもしれない。
- **メールの送信:** 登録の確かめ(認証コードなど)に、メールを送る仕組みが要る。
- **コードの公開:** 公開に向けて、秘密情報やメール送信の設定などは、環境ごとの設定に置く。
  - `local_settings.py` はすでに Git の管理から外してある。
