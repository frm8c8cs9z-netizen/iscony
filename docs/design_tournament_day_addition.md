# 設計メモ: トーナメントの当日追加(エントリー漏れ)

状態: **設計(2026-11-22 にユーザーと決めた内容)**。コードの変更はまだない。

## 背景

- リーグには、当日にエントリー漏れの組を足す画面がある(`2d30ddc`、[design_league_group_sizes.md](design_league_group_sizes.md) の「当日の追加の画面」)。あわせて組み合わせ確定もある([design_draw_confirmation.md](design_draw_confirmation.md))。
- 進出元のないトーナメント(例: 西日本の雨の日用の108組の表)にも、同じように当日に組を足す場面がある。
- ユーザー自身にトーナメントで当日に足した経験はない。下の決まりは、「紙の運用ならこうするのが自然」という判断で決めた。

## 決めたこと

### 番号

- 追加の組は、リーグと同じく、カテゴリの一番大きい番号の次を取る。ほかの番号は動かさない。

### 入れる場所の決まり: 既存の組Xを1つ選び、追加の組をXの最初の相手にする

試合が1つ増えるのは、Xのところだけ。開始回戦の配列([design_irregular_tournament.md](design_irregular_tournament.md))でいうと、Xが占めている範囲を半分に分け、上半分をX、下半分を追加の組にする操作になる。

- **A. Xに不戦がある場合(シードの組。開始回戦が2以上)**
  - 例: 1番が2回戦から、その下が不戦。33番を入れると「1番 対 33番」の1回戦ができ、1番は1回戦から出場になる。
  - ほかの組は何も変わらない。消えるのは、その不戦(S試合)の位置。
- **B. 不戦がない場合(32組ぴったりなど、全員が1回戦から)**
  - 表が1段深くなる。Xと追加の組が新しい1回戦を戦い、その勝者が、もともとのXの相手と戦う。
  - ほかの組は全員2回戦からになる。対戦相手は変わらない。
  - 例: 「1対2」「3対4」…の表で、X=2番を選ぶ。「2番 対 33番」の1回戦ができ、その勝者が1番と戦う。1番もほかの組も2回戦から。
  - 今の「1回戦」の試合は、呼び方が「2回戦」に変わる。
- **スーパーシード(3回戦から)をXにした場合**
  - 同じ決まりで、「X 対 追加の組」が2回戦にでき、両方とも1回戦は不戦になる。Xは「3回戦から」が「2回戦から」になる。
  - 起きにくい場面なので、この自然な結果のままでよい(ユーザーも「よくわからない」とのことで、特別な扱いはしない)。

### 指定がないときの入れる場所(Xの決め方)

- 運営側が場所を指定したら、そこに入れる(Xを選ぶ)。
- **ふつうの(自動の)表:** その組数+1組で表を作ったときに入る場所に入れる。
  - 2〜128組の全部で、組数が1つ増えると、標準の配置は必ず不戦が1つだけ埋まる形になることを確かめた(`build_standard_start_rounds(N)` → `(N+1)`)。そのため、この場所は1か所に決まる。
- **不戦がない表:** 1番の相手だった組(上から2番目の位置)をXにする。1番が「第一シード」になる形。
- **変則トーナメント(開始回戦を自分で指定した表):** 標準の場所がないので、Xを選んでもらう。

### マッチコード

- **ほかの試合のマッチコードは振り直さない**。紙の組み合わせ表や進行表を変えるわけにはいかないため。
- **増えた試合には、そのトーナメント表の一番大きいマッチコードの続きを付ける**(例: M31まであれば M32)。1回戦なのに大きい番号になるが、マッチコードは試合を見分けるためのもので、ずれない方が安全(ユーザーと一致)。
  - Bの場合も、今の「1回戦」の試合は、2回戦になってもコードはそのまま(M1はM1のまま)。
  - マッチコードはトーナメント表ごとに一意(`TournamentMatch` の `bracket, match_code`)。「一番大きい」も、そのトーナメント表の中で数える。

### 知らせ方

- 試合が増えた組(Xの組)には当然知らせる必要がある。ただ、本部から全体へのお知らせ(アナウンスなど)で足りる。
- そのため、組ごとの特別な表示は作らず、完了画面に何が変わったかを一覧で出す。
  - Aなら「1番の組は1回戦から出場になります」。
  - Bなら、それに加えて「1回戦だった試合は2回戦になります(対戦は変わりません)」。

### いつまで足せるか

- リーグと同じく、そのStageのどの試合にも結果が入っていない間だけ(`stage_has_results` が偽)。
- 確定したトーナメントStageでも足せる(確定で止めるのは事前セットアップの道具)。足したら、リーグと同じく自動で確定にする。

## 実装の前に確かめること(Claudeのメモ)

- 既存の試合の行(日程・マッチコード)を残したまま、表の形だけを変える必要がある。
  - Bでは、`round_number` / `match_number` / `next_match` / `next_slot` を付け直すことになる。`bracket, round_number, match_number` が一意なので、付け直す順に注意する。
  - 今の表を作る処理(`generate_tournament_bracket_matches`)は試合を全部消して作り直すので、そのままは使えない。
- `match_label` を進行表CSVなどで独自の名前にしている場合、増えた試合の `match_label` を何にするか。今は `match_code` と同じにする想定。
- 割り当て済みの日程(進行表)は、増えた試合だけ未配置にする。ほかの試合の日程は変えない。
- 後のStageの進出元(「表の勝者」など)の参照が壊れないこと。
- SVGの描画(片山・両山・分割表示)と印刷で、Bのように表が1段深くなった場合も崩れないこと。
- 取り消し(足した組を消す)と、その後に足し直したときのマッチコード(リーグの番号と同じく、一番大きいものの続きが戻る想定)。
- 画面: リーグの当日の追加の画面を、トーナメントにも使えるようにするか、別の画面にするか。
