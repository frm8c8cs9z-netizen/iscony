2026-11-26: 未使用画面の整理により、`court_status`、`pair_search`、`tournament_schedule_view`、`add_tournament_bracket`、`tournament_stage_overview_index`、単件配置API (`unassign_schedule_slot_api` / `move_schedule_slot_api`)、カテゴリスナップショット互換URL、`stage_group_order_maintenance` を削除。大会コード形式の公開URLも削除し、公開進行表・公開カテゴリ結果はトークン形式を使用する。トーナメント編集画面で共用する `add_tournament_bracket.html` は保持。


状態: **仕様・データの持ち方・作業の分け方を合意済み(2026-11-25)**。段階1から実装する。

## 背景

- 当日に試合の順番やコートを変えるとき、今は運営側の進行表(`schedule.html`)で各試合の「移動」リンクを押し、別画面(`move_schedule`)で行き先のコートと順番を選ぶ。
- ドラッグ&ドロップで動かせるのは、日程区分の配置画面(`schedule_block_detail`)だけ。事前に組むための画面である。
- 今の移動(`services/operations.py` の `move_schedule`)は、移動元のコートの後ろの試合を前に詰める。そのため、試合が動いたことが画面から分からない。
- 試合順の変更を、選手や来場者が気付けるようにしたい。

## 決めたこと

### 1. 進行表の操作をモード式にする

- 今は、各試合のセルに「審判」「結果入力」「結果表示」「採点票PDF」「移動」のボタン・リンクが並んでいる。
- これをやめて、画面上部で操作モードを選び、そのあとセルを操作する形にする。
  - モード: 審判 / 結果入力 / 結果表示 / 採点票PDF / 移動
- 日程区分の配置画面のモード切り替え(配置 / 移動 / 削除 / 他日程へ移動 / 審判)と、操作の考え方をそろえる。

### 2. 移動はドラッグ&ドロップで行う

- 「移動」モードで、試合をドラッグして行き先に落とす。
- **移動先:** 落とした位置に差し込み、その位置から後ろの試合を1つずつ繰り下げる。
- **抜け殻に落としたとき:** 同じく差し込みで、抜け殻も含めて後ろを繰り下げる。抜け殻は残る。
- **動かせない試合(今のルールのまま):** 呼出済・試合中・完了・結果入力済の試合(`Schedule.is_locked_for_move`)は動かせない。その前にも差し込めない。

### 3. 移動元には「抜け殻」を残す

- 移動元は前に詰めない。その位置に、試合がほかへ移ったことがひと目で分かる抜け殻を残す。
- **目的:** このコマの試合がどこかへ移動したことを、見た人が直感的に理解できるようにする。
- **目立たせる:** 控えめなグレーではなく、「移動済み」と分かる派手さを持たせる。見た目は見本を作って決める。
- **何が抜けたかを書く:** 繰り下げで抜け殻自体の番号もずれるので、位置ではなく抜けた試合を書く。
  - 例: 「移動済み M12 ○○・○○ 対 △△・△△ → Bコート 第5試合」
- **行き先はその時点の位置を出す:** 行き先の番号も、その後の繰り下げで変わる。保存した文字列ではなく、表示のたびに今の位置を引いて出す。
- **順番の枠を1つ使う:** 抜け殻がある限り、移動元のコートの後ろの試合の番号はそのまま。
- **残しっぱなし:** 本部が片付ける機能は作らない。
- **表示する場所:** 運営側の進行表と、一般公開の進行表(`public_schedule.html`)。
- **数えない:** 「次の試合」の判定や呼出の順番などからは、抜け殻を飛ばす。

### 4. 移動の履歴を持つ

- **元に戻す:** 新しい操作から1つずつ戻せればよい。途中の1件だけを選んで戻す機能は作らない。
- **お知らせへの利用(将来):** 試合順の変更を、一般向けのお知らせに使えるように記録しておく(下の「今回やらないこと」)。
- 似た仕組みとして、追加対戦への差し替えに `ScheduleReplacementHistory`(差し替えの記録と取り消し)がある。

### 5. データの持ち方(2026-11-25 合意)

- **抜け殻:** `Schedule` の行として残す。
  - 抜け殻の印と、移った先の `Schedule` への参照を持ち、試合は持たない。
  - 日程区分・コート・順番の重複禁止(`unique_together`)がそのまま効き、今の繰り下げ処理で抜け殻も一緒にずれる。
- **既定の `Schedule.objects` は抜け殻を除く。**
  - 抜け殻を含めて扱う入口は、並び替えの処理と進行表の表示に限る。
  - 「最後の順番+1」で採番する処理は、抜け殻も数えないと順番がぶつかるので見直す。
- **移動の履歴:** 別のテーブル(`ScheduleMoveHistory`)に持つ。
  - 動かした試合、抜け殻、移動元(日程区分・コート・順番)、移動先(コート・順番)、日時、操作した人、元に戻した日時。
  - `ScheduleReplacementHistory` にならう。
- **元に戻す:**
  - 大会の中で一番新しい、まだ戻していない移動を1つずつ戻す。
  - 戻すときは、試合を移動先から抜いて後ろを詰め、抜け殻の今の位置に試合を戻し、抜け殻を消す。
  - 試合に入った移動は戻せない。呼出済・試合中・完了・結果入力済(`is_locked_for_move`)が対象。一番新しい移動が戻せないときは、それより前の移動も戻せない。
- **行き先を選ぶ今の別画面(`move_schedule`)は廃止する。**
- **日程区分の配置画面(事前に組む画面)での移動は今までどおり。** 前に詰め、抜け殻は残さない。
  - 配置画面では抜け殻を見せるが、選ぶ・動かす・消すことはできない(2026-11-25 合意)。
- **日程区分をまたぐ移動もできる(2026-11-25 合意)。**
  - 日程区分は、日の違いだけでなく受付場所の違い(男子・女子など)でも分けるため。
  - 実施日の項目は持たず、どこへ動かすかは利用者の判断に任せる。
  - 画面では、日程区分をまたぐときだけ確認を出す(段階3)。
  - 抜け殻は元の日程区分に残り、元に戻すと元の日程区分へ戻る。
- **大会のコピーでは、抜け殻と移動履歴を写さない。** 空いた順番は詰める(2026-11-25 合意)。

### 7. 段階3の画面(2026-11-25 合意)

- **抜け殻の見た目(案A):**
  - 灰色の斜線の背景に、赤い「移動済み」の札を付ける。
  - 抜けた試合(カテゴリ・試合名・組)は取り消し線で出す。
  - 行き先は赤字で「→ Bコート 第5試合へ」と出す。
  - 運営側の進行表・一般公開の進行表・配置画面で同じ見た目にする。配置画面では触れない。
- **移動してきた試合の印:** 移動先の試合に、青い札で「Aコート第3試合から移動」と付ける。抜け殻と行き先の両方からたどれるようにする。
- **操作:**
  - マウスではドラッグ&ドロップで動かす。
  - タブレットでも使うので、「動かす試合を押す → 行き先のマスを押す」の2回押しにも対応する。
  - 日程区分をまたぐときだけ確認を出す。
  - 押せない試合(呼出済など)の前には差し込めない。差し込もうとしたら理由を出す。
- **元に戻す:** モードボタンの近くに「元に戻す」ボタンを置き、次に戻る移動を書いておく。押したら確認を出してから戻す。
- **今の移動画面(`move_schedule`)は廃止する。** 進行表メンテナンス画面の「移動」リンクもなくす。

### 8. 進行表メンテナンスの「編集」を管理用の道具として残す経緯(2026-11-25 合意)

- 進行表メンテナンス画面(`schedule_maintenance`、管理メニューから入る)の各行には「編集」(`edit_schedule`)がある。コート・順番・呼出/試合中/完了の印を直接書き換えられる。
- 「編集」でコートや順番を変えると、配置画面の移動と同じ `move_schedule` サービスで動く。移動元は前に詰め、抜け殻は残さず、移動の履歴(`ScheduleMoveHistory`)にも載らないので、元に戻す対象にもならない。
- 当日の移動は、進行表の「移動」モード(抜け殻と履歴が残る)に一本化した。そのうえで「編集」は、抜け殻を残さずに直接直したいとき(入力ミスの修正、事前の組み直し、抜け殻を作りたくない調整)のための管理用の道具として残す、とユーザーと決めた。
- 当日に「編集」で順番を動かすと、抜け殻が残らないため、試合が動いたことは画面から分からない。本部が必要と判断したときだけ使う前提で、通常の当日運営では進行表の「移動」モードを使う。
- 同じ日に、行き先を選ぶ旧来の移動画面(`move_schedule` ビュー)と、進行表メンテナンス画面の「移動」リンクは廃止した。「編集」は残した。
