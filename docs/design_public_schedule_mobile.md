# 一般公開の進行表:スマホ表示

2026-11-26 作成。12/19 の大会での利用を目指す。

## 背景

- 一般公開の進行表(`public_schedule.html`、URL は `public_schedule_view_token`)は、PC 向けの「試合順 × コート」の表になっている。
- iscony の全テンプレートに viewport 指定がない。そのためスマホは幅 980px の PC として描画して縮小表示し、16コートの大会では 4コート分しか見えず、文字も非常に小さい。
- viewport を足すだけでは、1画面に 1コートしか入らず、横スクロールが多くなる。
- 選手も来場者も、「自分の試合・あるコートの進み具合」と「全体の進み具合」の両方を見る。

## 決定事項

### 表示の切り替え

- スマホ幅のときは、最初にスマホ向けの表示(全体の様子とコートの縦一覧)を出す。
- PC 幅は今の表のままとする。
- スマホでも「表で見る」ボタンで今の表に切り替えられる。
  - 表の中は横スクロールにし、コート名(見出し行)と試合順(左列)を固定表示する。
  - 表の画面には「スマホ表示に戻る」を置く。
- 選んだ表示は、その端末に覚えさせる(localStorage)。
  - 読み書きは失敗してもよい作りにし、失敗した場合は既定の表示にする。
- ピンチによる拡大・縮小は止めない(`user-scalable=no` は使わない)。

### 全体の様子(スマホ表示で最初に開く画面)

- コートごとに「今」の試合と「次」の試合を、縦に並べる。
- 日程区分が複数ある場合は、区分ごとに見出しを付ける。
  - 最初は「今」を含む区分を開いて見せる。
  - 細部は実装時に詰める。
- コートを押すと、そのコートの縦一覧へ進む。

### コートの縦一覧

- 画面の上にコート番号のボタンを並べ、別のコートへ移れるようにする。「全体へ戻る」も置く。
- そのコートの試合を、試合順に上から並べる。
- 結果が入った試合は折りたたんで、1行(試合順とスコア程度)にする。
- 開いたとき、「今」の試合の位置まで自動でスクロールする。
- 抜け殻(移動済み)と「◯コート第N試合から移動」の札は、スマホでも出す。

### 「今」の判断

- 各コート・各日程区分で、**結果がまだ入っていない最初の試合**(抜け殻は除く)を「今」(試合中またはこれから)とする。
- その次の試合を「次」とする。
- 呼出済・試合中の状態は、運営画面から付ける手段が今はない(`update_schedule_status` はどこからもリンクされていない)。このため使わない。
- 結果入力が遅れると、表示も遅れる。これは了承済み。
- 運営側に「呼出・開始」の操作を足すかどうかは、12/19 の後に検討する。

### 検索(第2段)

2026-11-26 に詳細を決定。

- **置き場所:** スマホ表示の上、「全体の様子」の前に検索欄を置く。
  - 入力に合わせて結果を出し、検索ボタンは置かない。
  - 結果が出ているあいだは、全体の様子の代わりに結果一覧を出す。欄を空にすると全体の様子に戻る。
- **カテゴリ選択欄:** 置くが、初期値は「すべてのカテゴリ」とし、選ばなくても検索できる。選んだときは、名前・所属・番号のどの検索もそのカテゴリに絞る。
- **探せるもの:**
  - 名前:ペアのどちらかの一部。
  - 所属:一部一致。正式名・略称のどちらでも見つかる。画面の表示は大会の表示設定どおり。
  - 番号:数字だけの入力は、番号の完全一致にする(「5」で15番は出さない)。カテゴリ未選択なら、全カテゴリの同じ番号が出る。
- **表記ゆれ:** 全角/半角、ひらがな/カタカナ、空白や「・」の有無を吸収する。
- **結果の出し方:**
  - これからの試合を、日程区分・試合順の時間順に並べる。
  - 各行に、日程区分・コート・第◯試合・「あと◯試合」・対戦・カテゴリを出す。
  - 「あと◯試合」は、そのコートで結果未入力の試合(抜け殻を除く)のうち何試合後か。「今」の試合には「今」の札を付ける。
  - 終わった試合は、最後に「終わった試合(n)」として折りたたみ、スコアを付けて出す。
- **押したとき:** そのコートの縦一覧へ飛び、その試合の位置へスクロールして目立たせる。
- **検索語の記憶:** 最後の検索語とカテゴリを、その端末に記憶する(localStorage)。同じ端末を複数人で使うと前の検索が残るが、選手が開き直すたびに自分の試合が出る利便を優先した。
- **範囲:** 検索はスマホ表示だけの機能とし、「表で見る」には付けない。

### 実装の方針

- viewport は、公開ページだけに入れる。
  - base.html に block を用意し、公開ページの template だけが埋める。
  - 運営側の画面の見え方は変えない。
- 表示の切り替え・絞り込み・自動スクロールは、ページを読み込んだあとに端末側(JS)で行う。
  - サーバー側のキャッシュ(`public_view_cache`、5秒)には触らない。
  - クエリ文字列による出し分けもしない。
- 1回の HTML に、表とスマホ表示の両方の材料を入れる。
  - データは同じものを使う。
  - クエリ数は、データ量に比例して増えないようにする。

## 第1段のスマホ表示調整 (2026-11-26)

- 公開進行表だけで読み込むCSSの640px以下に限定し、ロゴ領域と「カテゴリ一覧」の固定表示を解除。ロゴは高さ40pxとする。
- 上部の固定要素がなくなるため、縦一覧のスクロール先は上端から16px空ける。
- 全体の様子は「1コート」等の見出し、今/次のバッジと試合順、対戦ペア、カテゴリ/グループの補助表示に分ける。右端の矢印でカードを押せることを示す。
- 表の高さは `calc(100dvh - 80px)` とし、`vh` をフォールバックにする。見出し行と左列の表内固定は維持する。

## スマホの「表で見る」のズーム (2026-11-26)

- 640px以下の表表示だけで、日程区分ごとの表内の2本指ピンチと「−」「＋」「全体」を提供する。1本指は縦横スクロールを維持する。
- 表要素のCSS `zoom` を使い、固定見出し・左列を維持する。ピンチ中心付近のスクロール位置を補正する。ラッパー内の標準ピンチとiOSのgestureイベントは抑止する。
- 全日程区分で倍率を共有する。最小倍率と「広く見る」ボタンは最も広い表が収まる倍率（下限20%、上限100%）、最大150%。多数のコートで20%でも収まらない場合は横スクロールする。ボタン名は当初「全体」だったが、16コートでは下限でも全コートが収まらず誤解を招くため「広く見る」にした（2026-11-26）。
- 倍率はlocalStorageに保存し、読み書きに失敗した場合は100%。スマホ表示に戻る場合とPC幅ではzoomを解除する。CSS zoom非対応環境ではズーム操作を表示しない。
