# 設計メモ: トーナメントの採点票の事前印刷と足の番号

状態: **足の番号は実装・コミット済み(596d260)。採点票の事前印刷も実装・コミット済み(2026-11-25)。実機プリンターでの位置確認と運用テストは未実施**。

## 背景

- 予選リーグは、最初から全試合の採点票をまとめて出力できる。
- トーナメントは、対戦する2組が決まった試合しか採点票を出力できない(`is_match_score_sheet_printable`)。そのため、2回戦から先は結果が入るたびに1枚ずつ出すことになる。
- 先日の大会で、全試合の採点票を前もって用意し、組が決まったら手書きで記入する方が早い場面があった。
- 採点票は、ほとんどの場合、前日までに印刷する。

## 決めたこと

### 1. トーナメントの全試合の採点票を前もって印刷する

- **対象:** 進行表(コートと順番)に入っている試合。S試合(不戦)は今までどおり対象外。
- **入口:** 一括出力画面の絞り込みフォームに「相手が決まっていない試合も出す(トーナメント)」のチェックボックスを置く。チェック時はコート別・トーナメント別の出力対象と件数に未確定試合を含める。チェックなしは従来どおり。
- **全体出力:** 「トーナメント全試合(相手未定を含む)」を追加。チェックの有無にかかわらず、進行表に入っている全回戦を日程区分→コート→試合順で出力する。Stage・コートの絞り込みに従う。
- **組が決まっている側:** 今までどおり、番号・所属・選手名を印字する。
- **組が決まっていない側:**
  - 番号・所属・選手名は空欄にし、現場で手書きする。
  - 名前の欄の上端に、その側に入りうる足の番号の範囲(例:「1〜4」)を印字する。
- **欄外(すべてのトーナメント採点票。組が決まった試合・1枚出力・1回戦一括も含む):**
  - 今の欄外の文字(「1日目 Aコート 第3試合」)とは別の位置で、**同じ高さの左端に近い位置**に印字する(2026-11-24 ユーザー)。
  - 試合名を印字し、その隣に、その試合全体に入りうる足の番号の範囲(例:「1〜8」)を印字する。
  - 試合名とマッチコードが違うときは「⑫(M12)」のように、試合名を先に、括弧の中をマッチコードにする。
  - 試合名があるときにマッチコードも印字するかは、大会の設定で切り替える(標準は印字する)。
- **範囲の出し方:** 試合の木(next_match / next_slot)をS試合も含めてたどり、下にある全枠の `leg_number` の最小〜最大を使う。開始回戦指定や当日追加で深くなった表も同じ。枝番は数えず、同じ足番号が1つだけなら「3」のように印字する。決まった側には範囲を印字しない。
- **範囲を印字する条件(2026-11-24 ユーザー決定):** 大会単位の表示判定で足番号が表示される表、または全枠の足番号がSVGに表示される組番号と一致する表に限る。不一致でStageの「出さない」を選んだ表は、未定側を空欄にし、欄外は試合名(+マッチコード)だけにする。
- 予選リーグの結果から組が入るトーナメント(進出元のある表)も、対象にする。

### 2. 足の番号(トーナメント表の上から順の番号)

- 紙の運用では、トーナメントに振った番号の範囲で試合を確かめ、進行表に記入したり、勝者を確かめたりしている。それと同じものを持つ。
- **組の番号(entry_code)とは別のもの。** 番号は予選の番号を後のStageでも使うので([design_numbering.md](design_numbering.md))、予選の後のトーナメントでは飛び飛びになり、範囲に使えない。
- 足の番号は、**組が埋まるまでの住所のような扱い**。トーナメント表の足に、上から1, 2, 3…と振る。
- **DBに持たせる。** 印刷した後で表をいじる必要が出たときに、刷った紙と突き合わせられるようにするため。
- **振り直さない。** マッチコードと同じく、刷った紙と食い違わないようにする。
  - 当日に組を足した場合([design_tournament_day_addition.md](design_tournament_day_addition.md))は、もとの組(X)の番号の枝番(例:「3の2」)を付ける。ほかの足の番号は動かさない。
- 採点票の範囲(上の1.)は、印字条件を満たす表に足の番号で出す。
- **振り始めの番号を指定できる**(2026-11-24 ユーザー)。カテゴリをまたいで同じ番号を使いたくない作成者がいるため(例: 男子Aは1から、女子Aは101から)。
  - Stageの設定に「足の番号の振り始め」を持つ(標準は1)。
  - 1つのStageにトーナメント表が複数あるときは、表の順に続き番号で振る(例: 101〜132、133〜164)。同じStageの中で番号が重ならないようにするため。
  - あとから振り始めを変えたら、全部の足を同じ幅だけずらす(並びと枝番はそのまま)。刷った紙と食い違うので、変更するときに「印刷済みの採点票・トーナメント表と番号が変わります」と注意を出す。
  - 振り始めが1以外なら、進出元のない表でも組の番号と食い違うので、標準では足の番号を出すことになる。

### 3. 足の番号の表示(SVGと印刷)

**大会単位で表示を揃える(2026-11-24 ユーザー決定、A案)。**

「出す理由がある表」は、進出元のある枠を持つ表、または組の番号と足の番号に1つでも食い違いがあり、Stageの「足の番号を出す」が有効な表。
大会内に1つでも出す理由がある表があれば、番号がすべて同じ表にも「(1) 1」のように出す。

| 大会・表の状態 | 足の番号の表示 |
|---|---|
| 進出元のある表 | Stageの設定にかかわらず、いつも出す |
| 大会内に出す理由がある表があり、このStageの「足の番号を出す」が有効 | 組の番号とすべて同じ表にも出す |
| 進出元がなく、このStageの「足の番号を出す」が無効 | 他の表に出ていても、この表には出さない |
| 大会内のどの表にも出す理由がない | どこにも出さない |

- 選ぶ場所はStageの設定。標準は「出す」。Stageのない旧来の表は、有効として扱う。
- 横断表示、表1枚の画面、トーナメント印刷など、共通SVGビルダーを使うすべての画面で同じ判断にする。
- 大会全体の判定は1回のDB問い合わせで取得し、リクエスト内で共有する。カテゴリ・表・SVG分割数に比例して判定の問い合わせを増やさない。
- 足の番号は外側の専用列に、括弧付きで大きく出す。組番号を四角で囲む審判の表示と区別する。
- 画面のSVGだけでなく、**印刷にも出す**。片山・両山・分割表示で同じ判断とする。

### 表示順を足の番号に使わない理由

表示順は表の上からの位置で、多くの処理が1からの並びとして使っている。
当日の追加で位置がずれても、印刷した紙と照合する住所は動かしてはいけないため、足の番号は別に持つ。
CSVの表示順も、リーグと同じ意味のまま揃える。

## 足の番号を振る・残す場面(コードを調べて決めた案、2026-11-24)

表を作る・作り直す処理は、`generate_tournament_bracket_matches` に集まっている。Stageの編集、Stage枠CSV、組み合わせの作り直しは、どれもここを通る。

| 場面 | 足の番号 |
|---|---|
| 表を作る・作り直す(`generate_tournament_bracket_matches`) | Stageの振り始めから、表の順に続き番号を振る。作り直す表の枝番は消すが、他の表の当日追加の枝番は残す。前の表の組数が変われば、後ろの表の番号もずれる。Stage全体の作成では全体を振り直す。作り直しではマッチコードも変わるので、刷った紙は使えなくなる。 |
| 組の割り当て・入れ替え・移動(枠は動かず、中の組が動く) | 変えない |
| 当日の追加 | 追加した足に、Xの番号の枝番(「3の2」)を付ける。取り消すと、その足ごとなくなる。 |
| 大会のコピー、バックアップ・復元、スナップショット | 足の番号も写す |
