# 管理画面の遷移と役割

このメモは、`iscony` の管理系画面について、
「どこから入るか」「どこまで掘れるか」「各画面が何を担当するか」をひと目で追えるように整理したものです。

対象は主に大会運営・準備・メンテナンス画面です。
公開画面は別導線として扱い、この文書では管理側を中心にまとめます。

## 1. 全体方針

- ロゴ下の大会メニューを、管理側の常設主導線とする。
- 大会詳細ページは、大会全体の入口としてカテゴリ入口と公開表示の確認をまとめる。
- 管理メニューは、当日運営、構成管理、設定、危険操作をまとめる。
- `Stage` は内部実装上の概念であり、運営者には前面に出しすぎない。
- 当日運営は、`試合選択`、`QR/キー検索`、`進行表` の3本を中心に回す。

## 2. メニューの階層

### 2.1 いちばん上

```text
ロゴ下の大会メニュー
  ├─ 試合選択
  ├─ QR/キー検索
  ├─ 進行表
  ├─ 大会詳細
  ├─ 大会スナップショット
  ├─ 公開表示
  └─ 管理メニュー
```

ここは常設の主導線です。
どの画面からでも戻るための入口であり、本文側の個別ボタンより優先します。

### 2.2 大会詳細

```text
大会詳細
  ├─ カテゴリ入口
  │    └─ カテゴリ Stage進行
  │         ├─ リーグ表
  │         │    └─ リーグ結果入力 / リタイア / 順位確認 / 追加対戦
  │         └─ トーナメント表
  │              └─ トーナメント結果入力 / 進出元確認 / 採点票 / メンテ
  └─ 公開表示
       ├─ 大会トップ
       ├─ 試合進行表
       └─ カテゴリ別結果
```

大会詳細は、カテゴリをたどる出発点です。
ここから先は「カテゴリを選ぶ → カテゴリの中のStageを見る → 必要なら個別入力や表確認に進む」という流れになります。

### 2.3 管理メニュー

```text
管理メニュー
  ├─ 運営ハブ
  │    ├─ 試合選択
  │    ├─ QR/キー検索
  │    ├─ 採点票一括出力
  │    ├─ 試合進行表
  │    ├─ 進行メンテナンス
  │    └─ 大会スナップショット
  ├─ 構成管理
  │    ├─ 進出元一覧・入れ替え
  │    ├─ Stage補助一覧
  │    ├─ 各カテゴリのリーグ枠調整
  │    ├─ トーナメント一覧・個別設定
  │    ├─ カテゴリ・リーグ表示順
  │    ├─ コート表示順
  │    └─ 大会設定
  └─ 危険操作・初期化
       ├─ 参加者CSV取込
       ├─ Stage枠CSV取込
       ├─ 現在のStage枠CSV
       ├─ 試合進行CSV取込
       ├─ フォーマット
       ├─ 大会複製
       └─ カテゴリ追加
```

管理メニューは、運営に必要なものを上から見せ、構造を触るものは下へ寄せています。

## 3. 入口ごとの深い階層

### 3.1 試合選択

```text
試合選択
  ├─ カテゴリから入る
  │    └─ カテゴリ Stage進行
  │         ├─ リーグ表
  │         ├─ トーナメント表
  │         ├─ 試合入力
  │         └─ 進出元や後続反映の確認
  └─ 進行枠を選ぶ
       ├─ コートを選ぶ
       └─ 試合順を選ぶ
            └─ 該当試合の結果入力
```

#### 役割

- 結果入力の主導線。
- 「進行枠 → コート → 試合順」で対象を絞る。
- カテゴリ単位で入る場合は、`カテゴリ Stage進行` へ寄り道してもよい。

#### 画面の見え方

- `カテゴリから入る` はカテゴリ一覧のボタン群。
- `進行枠を選ぶ` は日程や用途の切り替え。
- `コートを選ぶ` と `試合順を選ぶ` は、現場での検索補助。
- 候補一覧では、リーグとトーナメントを同じ表で見せる。

### 3.2 QR/キー検索

```text
QR/キー検索
  └─ match_key / QR 読み取り
       └─ 試合入力
            ├─ 結果入力
            └─ 確認
```

#### 役割

- スコアシートの QR や `match_key` から対象試合を直接探す入口。
- 現場で迷った時の補助導線。
- 読めない端末では手入力へ落とす。

#### 画面の見え方

- 手入力とカメラ読み取りを選べる。
- 読み取り成功後は対象試合の検索結果を自動表示する。

### 3.3 進行表

```text
進行表
  ├─ 試合カードの確認
  ├─ 結果入力
  ├─ 採点票PDF
  ├─ 試合順変更
  ├─ コート変更
  └─ コート状況確認
```

#### 役割

- 当日運営の中心画面。
- コートごと、試合順ごとに進行状況を見る。
- 呼出、試合中、完了更新の基準になる。

#### 画面の見え方

- 当日運営では、試合カードとして情報を要約して出す。
- 横に長いが、ヘッダ固定や行ラベル固定で追いやすくする。
- 一般参加者向けの進行表とは役割が違う。

### 3.4 大会スナップショット

```text
大会スナップショット
  ├─ スナップショット一覧
  ├─ 大会全体復元
  ├─ カテゴリ復元
  ├─ 日程区分復元
  └─ 進行表だけ復元
```

#### 役割

- 大会全体の退避・復元を扱う。
- 誤入力、誤反映、進行トラブルへの備え。
- カテゴリ単位だけでなく、大会全体の基準に戻す。

#### 画面の見え方

- 一覧から復元対象を選ぶ。
- どこまで戻るかが一目でわかるようにする。

### 3.5 進行メンテナンス

```text
進行メンテナンス
  ├─ 進行表の確認
  ├─ 未配置トーナメント試合の追加
  ├─ 試合順の調整
  └─ コートや配置の微修正
```

#### 役割

- 進行表の修正・補助作業。
- 当日の事故対応にも使うが、毎回触る場所ではない。

#### 画面の見え方

- 一般の受付導線とは分ける。
- 補助機能として残し、普段は進行表から操作する。

### 3.6 Stage補助一覧

```text
Stage補助一覧
  └─ カテゴリ一覧
       └─ 各カテゴリの Stage進行
```

#### 役割

- カテゴリごとの `Stage進行` への入口だけをまとめる。
- 現在は補助ページとして扱う。

#### 画面の見え方

- 画面そのものは主役ではなく、カテゴリの入口集。
- 将来は `Stage` を前面に出さず、カテゴリ作業一覧へ寄せる候補。

### 3.7 進出元一覧・入れ替え

```text
進出元一覧・入れ替え
  ├─ Stageごとの進出元確認
  ├─ 進出元の入れ替え
  └─ 後続Stageへの反映確認
```

#### 役割

- 後続 Stage に何が入るかを管理する。
- 結果修正や同率処理のあとに、進出先を直す時に使う。

#### 画面の見え方

- 運営者には「どこからどこへ流れるか」の確認画面として見せる。
- 内部の `source_*` より、結果の流れが読める表示を優先する。

### 3.8 各カテゴリのリーグ枠調整

```text
リーグ枠調整
  ├─ リーグ枠一覧
  ├─ 枠の確認
  ├─ 枠の修正
  ├─ リタイア / 取消
  └─ 試合入力への確認
```

#### 役割

- そのカテゴリのリーグ枠を直接整える。
- 当日よりも準備・事故対応寄り。

#### 画面の見え方

- 表示はカテゴリ単位。
- リーグ表の確認と枠メンテは分けて考える。

### 3.9 トーナメント一覧・個別設定

```text
トーナメント一覧・個別設定
  ├─ トーナメント一覧
  ├─ 各トーナメント表
  │    ├─ 結果入力
  │    ├─ 進出元確認
  │    ├─ 表示設定
  │    └─ メンテナンス
  └─ 未配置試合の追加
```

#### 役割

- カテゴリをまたいでトーナメント表へ移動する入口。
- 結果入力、表示設定、メンテナンスに分岐する。

#### 画面の見え方

- 一覧は入口、個別設定は深い操作。
- 今後は、結果入力を主とする画面と、カード確認用の画面を分けたい。

### 3.10 カテゴリ・リーグ表示順 / コート表示順

```text
表示順調整
  ├─ カテゴリ・リーグ表示順
  └─ コート表示順
```

#### 役割

- 画面の並びや進行表の見せ方を整える。
- 運営の視線の流れを調整する。

#### 画面の見え方

- データ構造を変えるというより、見え方の順序を決める。

### 3.11 大会設定

```text
大会設定
  ├─ デフォルトのリーグ表示方式
  ├─ デフォルトのトーナメント表示方式
  └─ デフォルトのレイアウト方式
```

#### 役割

- 大会ごとの標準表示を決める。
- リーグ・トーナメントの見せ方や初期値をまとめる。

#### 画面の見え方

- 大会オーナー向けの設定。
- 当日オペレーターは原則ここを触らない。

### 3.12 CSV取込

```text
CSV取込
  ├─ 参加者CSV取込
  ├─ Stage枠CSV取込
  │    └─ 現在のStage枠CSV
  ├─ 試合進行CSV取込
  │    └─ フォーマット
  └─ 大会複製 / カテゴリ追加
```

#### 役割

- 大会の初期投入や再構成。
- 手入力を減らすための準備導線。

#### 画面の見え方

- 一括更新に近いので、警告と確認を厚くする。
- 既存の進行表や結果がある場合は、消える可能性を明示する。

### 3.13 高度なメンテナンス

```text
高度なメンテナンス
  ├─ 旧リーグ枠CSV取込
  ├─ 旧検索
  ├─ 手入力のリーグ生成
  ├─ 手入力のトーナメント追加
  └─ 細かい修正系
```

#### 役割

- 旧実装や手入力中心の機能を置く。
- 今後のオンライン作成UIに吸収できるものは、ここから整理する。

#### 画面の見え方

- 普段は前面に出さない。
- 必要な時だけ触る補助領域。

## 4. 画面ごとの役割一覧

### 4.1 大会詳細

- 大会全体の入り口。
- カテゴリ入口と公開表示の確認ができる。
- 管理上の各カテゴリにはここから進む。

### 4.2 試合選択

- 結果入力の起点。
- 進行枠・コート・試合順から探す。
- カテゴリから直接入る道もある。

### 4.3 QR/キー検索

- 試合をキーで特定する。
- カメラ読み取りと手入力の両方を想定する。

### 4.4 進行表

- 当日の試合進行を見て回す。
- 呼出、進行、完了、移動、入力のすべての基準。

### 4.5 カテゴリ Stage進行

- 1カテゴリ内のリーグとトーナメントを縦に追う。
- 反映待ちや未確定情報もここで見る。

### 4.6 リーグ表

- 試合結果、順位、リタイア、追加対戦を扱う。
- 後続 Stage への反映元になる。

### 4.7 トーナメント表

- 勝ち上がりと進出元を追う。
- SVG 表示やカード表示の土台になる。

### 4.8 大会スナップショット

- 事故対応の復元元。
- 大会全体の安全網。

### 4.9 採点票一括出力

- 印刷可能な試合をまとめて出す。
- コート別、リーグ別、トーナメント別に確認できる。

### 4.10 進行メンテナンス

- 進行表の調整や未配置試合の追加。
- 当日の詰まりをほどく。

### 4.11 Stage補助一覧

- カテゴリ Stage進行への補助入口。
- 入口の整理をする場所。

### 4.12 進出元一覧・入れ替え

- 後続 Stage の流れを調整する。
- 自動反映と手動修正の境目にある。

### 4.13 表示順調整

- 画面の並びと視線の流れを整える。

### 4.14 大会設定

- 大会の初期表示やレイアウトの標準を決める。

### 4.15 CSV取込

- 参加者、枠、進行表を一括投入する。
- データの大きな入り口。

### 4.16 高度なメンテナンス

- 旧導線、手入力導線、補助機能。
- 長期的には整理・統合候補。

## 5. よくある操作の流れ

### 5.1 結果入力

1. ロゴ下の大会メニューから `試合選択` へ入る。
2. 進行枠、コート、試合順で絞る。
3. 必要なら `カテゴリ Stage進行` へ入って、カテゴリの流れを確認する。
4. 該当試合の結果入力画面へ進む。

### 5.2 QR やキーで試合を探す

1. ロゴ下の大会メニューから `QR/キー検索` へ入る。
2. `match_key` または QR を使って対象試合を特定する。
3. 試合入力または確認画面へ進む。

### 5.3 進行表を見ながら運営する

1. ロゴ下の大会メニューから `進行表` へ入る。
2. 試合カードを見ながら呼出、進行、完了を回す。
3. 必要に応じて結果入力、採点票出力、試合順変更へ進む。

### 5.4 カテゴリ全体を確認する

1. `大会詳細` からカテゴリを選ぶ。
2. `カテゴリ Stage進行` でリーグ表とトーナメント表を縦に見る。
3. 後続 Stage への反映や未確定の有無を確認する。

### 5.5 事故対応

1. `大会スナップショット` を開く。
2. 必要な範囲を確認して戻す。
3. 反映元の結果や後続 Stage の状態を見直す。

## 6. 今後の整理方針

- 管理導線は、共通メニューを主軸にする。
- 同じ意味のリンクをページごとに増やしすぎない。
- `Stage` を前面に出しすぎず、カテゴリ単位の作業感へ寄せる。
- 将来は、結果入力モーダル、検索方法の選択、権限分離、タブレット対応をこの遷移図に沿って育てる。
- 旧CSV取込や旧検索は、必要性が薄れたら整理候補に回す。
