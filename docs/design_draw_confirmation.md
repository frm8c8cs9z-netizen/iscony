# 設計メモ: 組み合わせ確定(確定後は番号と組み合わせの形を変えない)

状態: **実装済み(2026-11-19〜22)**。設計は2026-11-18にユーザーと決めた内容。実装で決めたことは末尾の「実装で決めたこと」にまとめた。

## 背景

- 当日の追加(`2d30ddc`、[design_league_group_sizes.md](design_league_group_sizes.md) の「当日の追加の画面」)で、入れるグループを間違えた場合、今はStage編集で組数を変えて割り当て直すしかない。Stage編集は事前セットアップ用の道具なので、番号を上から振り直してしまう。
- 番号は、カテゴリの中で一意の抽選番号として、配った後は変えない([design_numbering.md](design_numbering.md))。
- そこで、組み合わせを印刷・公開した後に、番号と組み合わせの形が変わる操作を止める「組み合わせ確定」を作る。あわせて、当日の追加の画面に「グループを移す」を足す。

## 今すぐできる回避策(実装前)

- 当日の追加の画面で、その組を「取り消し」してから、正しいグループに追加し直す。最大の番号が戻るので、同じ番号(例: 10)が付く。ほかの番号は動かない。名簿の入力はやり直しになる。

## 決めたこと

### 確定の単位

- **進出元のないStage**(`advancement_source_stage` が空。カテゴリの最初のStage)ごとに確定する。リーグもトーナメントも対象。
  - 人が呼ぶ番号(抽選番号)は、このStageで決まり、後のStageでも使う。ここを守れば番号は守られる。
  - 当日の追加が使えるStage(進出元のないリーグ)とも一致する。
- 進出元のあるStage(後のStage)は対象外。後のStageの枠の番号は人が呼ぶ番号ではないため。
  - 決勝トーナメントの表をプログラムに印刷する場合、確定していない後のStageを編集すると、印刷した形と変わる可能性は残る。これは「番号」ではなく「印刷した形」の問題として、困ったら後のStageにも確定を広げる。

### 確定の操作

- Stage管理(またはStage編集)に「組み合わせを確定する」ボタンを置く。印刷・公開したときに運営者が押す(Isconyには、いつ配布したかが分からないため、人が押す)。
- **当日の追加をしたら、そのStageを自動で確定にする**(追加したということは配った後のはず。押し忘れを防ぐ)。
- **確定の解除は、今は誰でもできる**。解除するとき「解除すると、編集で番号が振り直されることがあります」と確認を出す。権限の整理をするときに見直す。
- 結果が入った後のロック(`stage_has_results`)は、今までどおり別にかかる。確定は、それより手前の段階で番号と形を守る位置づけ。

### 確定したStageで止める操作(番号や組み合わせの形が変わる道)

- Stage編集での枠の作り直し(参加ペア数・グループ数・組数の変更、組数の並びだけの変更で割り付けを残す場合も含む)。名前・ゲーム数の変更はできる。
- トーナメントの開始回戦の変更(割り付けを残す変更も含む)。番号が動かなくても、組み合わせの形が変わるため。
- Stage枠CSVの取り込み直し(`import_stage_slots`)で、そのStageの枠を作り直すこと。
- ペア割り付けの画面の、+1枠の追加・解除、+1枠を未割り当てに戻したときに枠ごと消して番号を詰める処理。
- グループの削除(`delete_group_confirm`)、トーナメント表の削除(`delete_tournament_bracket_confirm`)、Stageの削除(`delete_stage_confirm`)。確定を解除してから行う。
- 名簿でのエントリー番号の書き換え(`edit_participant`)。確定したStageに入っている参加者の番号は変えられない。名前・所属などは今までどおり直せる。

### 確定しても使える操作

- 当日の追加・取り消し・グループを移す(下)。
- 選手変更(当日の差し替え)、棄権など、番号を動かさない操作。
- 名前・所属などの名簿の修正、Stageの名前・ゲーム数の変更。
- 進行表(日程)の編集、進行表CSVの取り込み。

### 対象外(今のまま)

- バックアップ・スナップショットからの戻し(大会全体を巻き戻す管理者向けの操作)。

## 当日の追加の画面に「グループを移す」を足す

- 入れるグループを間違えたときのための操作。対象は、当日の追加で足した組だけ。
- 番号はそのまま、別のグループの最後に移す。元のグループでの試合と日程を消し、移した先で試合を作る(日程は未配置)。両方のグループの記録した組数(`planned_slot_count`)を直す。
- 使えるのは、その組の試合に結果が入っていない間だけ。
- 「取り消して追加し直す」と違い、名簿の入力をやり直さずに済む。

## この後に詰めること: トーナメントの当日追加(2026-11-18 ユーザー)

- 進出元のないトーナメント(例: 西日本の108組の表)にも、当日のエントリー漏れを足すパターンがある。今のリーグの当日追加とは別に設計する。
- 検討が必要なこと: どの不戦(Bye)を消して組を入れるかを指示する画面、増えた試合のマッチコードの振り方。
- 確定したトーナメントStageでも、この当日追加はできるようにする前提(確定で止めるのは事前セットアップの道具)。

## 決めること(実装前)

- 確定の状態は `Stage.draw_confirmed_at`(確定した日時)に持つ(マイグレーション 0062)。Stage管理の一覧に「確定済み」を表示する。
- 止めた操作のボタン・欄は隠さず、押せない状態にして理由を一文添える(確定に気づかず迷うのを防ぐ)。

## 実装で決めたこと(2026-11-19〜22 ユーザー)

- 確定したStageで止めた道は、上の一覧に加えて次も止めた: 番号(pair_code)・表示順の直接の書き換え、リーグの並び替え、トーナメントの参照枠の変更、グループの順番の変更、管理サイト(Django admin)からの構造の編集。
- 名簿CSVの取り込みは、対象カテゴリの参加者が確定したStageに入っている間は、まるごと止める。直したいときは確定を解除して取り込み、また確定する。
- **結果が入ったStageでは、確定していてもゲーム数を変えられない**(名前・表示順だけ)。結果が入ったStage全体のゲーム数を後から変える仕組みは、特別な修正メニューとして別に検討する。終わった試合の点数が新しいゲーム数に合わなくなる問題がある(例: 7ゲームマッチの4-2 → 5ゲームマッチ)。
- **ペア割り付けの画面の参加者の割り当て・移動・入れ替え(+1枠以外)は、確定したStageでも止めない**。番号は動かないうえ、配った後に抽選の入れ違いに気づいたときに直す道になるため。誤ってドラッグする事故が実際に起きたら、確認の表示などを考える。
- 当日の追加をしたら、未確定のStageは自動で確定にする。取り消しでは確定を解除しない。
- 「グループを移す」は、当日の追加・取り消しと同じく、**Stageに結果が入っていない間だけ**使える(試合が始まる前に整理できているはず)。
  - 試合が進んでから運営側の設定の不備に気づいたときの直し方は、別のテーマとして検討する。
- **移す・取り消すで元のグループの組数が減り、後のStageの枠や進行表の審判の指定が参照している順位(例: 3組になったグループの「4位」)がなくなるとき**は、操作は止めず、押す前の確認ダイアログと押した後のメッセージ(見直す画面へのリンク付き)で知らせる。参照の指定は消さない(直す場所の手がかりとして残す)。
  - 当日は本部が慌ただしく、後のStageへの影響まで気が回らないことがあるため。
  - **暫定の扱い**。運用状況を見て、止める・文言を変えるなどの変更はあり得る。
