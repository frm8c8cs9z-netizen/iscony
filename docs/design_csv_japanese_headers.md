# 設計メモ: CSVヘッダの日本語エイリアス

状態: **実装済み(2026-11-24)**。見出し名と出力の順番は、使ってみてから見直す可能性がある。2026-11-06 にユーザーと話し、2026-11-24 に下の「決めたこと」を決めた。

## 困っていること

CSV取込のヘッダは英語のコード名(`category`、`entry_code`、`player1_name`、`org1` など)だけを受け付ける。大会運営者が Excel で名簿を作るとき、英語のヘッダは分かりにくく、打ち間違えやすい。一般リリースの前に、日本語のヘッダ(例:「カテゴリ」「参加者コード」「選手1」「所属1」)でも取り込めるようにしたい。

`participant_db_design.md` の第1段階の決定では「日本語ヘッダ対応は第1段階では実装しない」としていた。このメモはその続き。

## 現状(2026-11-06 時点)

- CSVの処理は `core/views/csv.py` にまとまっている。
- 取込は3種類: 参加者(`participants`)、Stage枠(`stage_slots`)、進行表(`schedule`)。ヘッダの一覧は `CSV_FORMAT_HEADERS`。
- 3種類とも `_read_csv_rows()` で `csv.DictReader` を作り、値は `_cell(row, key)` か `row.get(key)` で英語のキー名で読む。
  - そのため、`_read_csv_rows()` でヘッダ名を英語の正式名に置き換えれば、各取込処理を変えずに済む見込み。
- 別名は、所属の列だけ個別に持っている(`organization1`〜`organization5` を `org1`〜`org5` として読む)。
- 値の側には、すでに日本語を受け付けているものがある(勝ち上がりの `勝者`/`敗者` など)。
- 文字コードは UTF-8(BOM可)だけを読む(`decode("utf-8-sig")`)。

## 検討すること

- **別名の表:** 英語の正式名 → 日本語の別名(複数可)を、取込の種類ごとに1か所で定義する。所属の列の既存の別名も、ここへまとめる。
- **所属の列名:** 大会ごとに所属の名前(`TournamentOrganizationField.label`)を変えられるようにする予定がある。そのとき、ヘッダもその名前で読むか。
- **ゆれの吸収:** 全角と半角、空白、括弧の違いをどこまで同じ名前として扱うか。
- **重複:** 同じ列を英語と日本語の両方で書いた場合は、エラーにするか、どちらかを優先するか。
- **書き出しとひな形:** CSVの書き出しとひな形を日本語ヘッダにするか、英語のままにするか、選べるようにするか。取込み直す運用(書き出す → 直す → 取込む)が往復できること。
- **エラーメッセージ:** 「category がありません」ではなく、運営者が書いたヘッダの名前で伝える。
- **文字コード:** Excel で「CSV」として保存すると Shift_JIS(cp932)になることが多い。日本語ヘッダに対応するなら、Shift_JIS の読み込みもあわせて検討する(UTF-8 として読めなければ cp932 で読む、など)。
- **今後増えるCSV:** 審判の取込(`design_umpire_csv.md`)など、これから作るCSVも同じ仕組みに乗せる。

## 決めたこと(2026-11-24 ユーザー)

### 見出し名(英語の正式名 → 日本語名)

今の英語の見出しも、そのまま読める。日本語名は次のとおり。

- **参加者名簿:** category=カテゴリ、entry_code=番号(「参加者コード」「エントリー番号」でも読む)、player1_name=選手1、player2_name=選手2、organization=所属、org1=所属1、org2=所属2、player1_org1=選手1所属1、player1_org2=選手1所属2、player2_org1=選手2所属1、player2_org2=選手2所属2
- **Stage枠:** category=カテゴリ名、stage_code=ステージコード、stage=ステージ名、stage_type=形式、group=リーグ名、bracket=トーナメント名、slot_label=枠名、display_order=表示順、entry_code=番号、source_type=進出元の種類、source_stage=進出元ステージ名、source_stage_code=進出元ステージコード、source_bracket=進出元トーナメント名、source_group=進出元リーグ名、source_rank=進出元順位、source_match=進出元マッチコード、source_result=進出元マッチの勝敗、match_games=ゲーム数、start_round=開始回戦
- **進行表:** schedule_block=日程区分、category=カテゴリ名、stage_code=ステージコード、stage=ステージ名、group=リーグ名、bracket=トーナメント名、court=コート、order=順番、slot1_code=枠1、slot2_code=枠2、meeting_number=何回目、match_code=マッチコード、match_label=試合名、match_games=ゲーム数、umpire_entry_code=審判番号(読むだけの stage_type は「形式」)
- 書き出し・ひな形には上の名前を使う。読み込みでは、最初の案の名前(カテゴリ/カテゴリ名、Stage・ステージ、グループ、トーナメント表、進出元試合、進出元の勝敗など)も別名として受け付ける。
- **見出し名と出力の順番は、実装後に見直す可能性がある**(2026-11-24 ユーザー)。名前も順番も1か所の定義を変えるだけで済むようにする。読み込みは列の名前で読むので、順番を変えても取り込みには影響しない。
- 今ある別名(organization1〜5、旧形式の pair1/pair2 など)も、引き続き読む。

### 細かい決まり

- **ゆれの吸収:** 全角・半角、空白、英字の大文字・小文字の違いは同じ見出しとして扱う。括弧の違いは吸収しない。
- **同じ列が2回:** 同じ正式名になる列が2つ以上ある(例:「番号」と「entry_code」)ときは、エラーにする。
- **エラーの文言:** 運営者が書いた見出しの名前で伝える。CSVにない必須列は日本語名で伝える。
- **文字コード:** UTF-8(BOM可)として読めなければ、Shift_JIS(cp932)として読む。書き出しは今のまま、BOM付きUTF-8。
- **取り込み画面の説明の表:** 「番号(entry_code)」のように、日本語と英語を並べる。
- **大会ごとの所属の名前:** 今回はやらない。見出しは「所属1」「所属2」に固定。

### ひな形と書き出し

- ひな形も書き出しも、**標準は日本語の見出し**。
- **英語の見出し(正式名)でも出力できるように、選べる形にする。** 運営向けではなく、開発者(ユーザー)が元の見出しを確認するため。
  - 各ダウンロードの入口(取り込み画面・管理メニュー)の横に、小さく「英語の見出しで出力」のリンクを置く。普段のリンクは日本語。
- どちらで書き出しても、そのまま取り込み直せる。
