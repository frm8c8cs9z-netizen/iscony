## 背景

- 紙で運営した大会で、大会側がエントリーを漏らしていて、試合が始まる前に、途中のグループへ1組足す対応が起きた。
- 印刷したリーグ表を事前に準備していたため、番号を振り直すことは実質できなかった。手書きでグループに1行足し、番号をとばして付けた(例: 10,11,12 → 10,11,12,42)。
- 受付をした参加者には、紙のプログラム(冊子)を配っている。当日の追加は、プログラムに反映できない。番号を振り直すと、選手の手元のプログラムとも番号がずれる。
- 番号の考え方は [design_numbering.md](design_numbering.md) のとおり。番号は、カテゴリ内で一意の抽選番号として、大会を通して変えない。

## Stage作成時に+1にするグループを選ぶ(Aの拡張)

- トーナメントの開始回戦と同じ考え方にする。**指定がなければ今までどおり若いグループから+1、指定したいときはグループごとの組数を並べて入れる**(例: 4,4,5,4,4)。
  - +1にするグループの印だけを並べるより、紙の組み合わせ表を見たまま入れられる。
- 検証:
  - 合計が参加ペア数と同じ。
  - グループ数と同じ数だけ並んでいる。
  - 各グループ3組以上(今のグループ分けの決まり `build_group_count_candidates` と同じ)。
  - **組数の差は1まで**(ユーザー決定 2026-11-16)。例えば 3,5,4 は不可。
- 番号は、今までどおり上から順に振る(連番のまま)。
- Stage編集でも同じ欄を出し、今の値を入れておく。
- **どのグループが+1かは、作成時に決めた組数を記録して判断する**(下の「調べて分かったこと」1)。

## 臨時で組を足す処理(B、新規)

- 足すグループと組数を選ぶ。2組以上も足せる。
- 足した枠の番号は、そのStageの最後の番号の次から付ける。ほかの枠の番号は動かさない。
- 足した組と、そのグループのほかの組との**総当たり試合を作る**(今の「+1枠を追加」は試合を作らない。下の「調べて分かったこと」3)。
- 作った試合は、進行表へ**ドラッグ&ドロップで入れられる**ようにする(現場で起きることを想定)。今の進行表の「配置」モード(未配置の試合を置く)で足りるか、追加試合と同じ扱いが要るかは、実装前に確かめる。
- **結果が入った後は、追加できなくてよい**(ユーザー決定 2026-11-16)。そのグループ(またはStage)に結果が1つでも入っていたら、追加できないようにする。
- 置き場所(メニューのどこから入るか)は未定。当日の修正の側(選手変更・棄権など)が候補。

## 調べて分かったこと(2026-11-16 時点のコード)

1. **どのグループが+1かを、決まりで毎回計算している。**
   - `core/services/stage_setup.py` の `group_base_size` は、参加ペア総数(`group_slot_reference_total`)・グループ数・`display_order` から、「若いグループから+1」の決まりで本来の枠数を計算している。
   - 「+1枠を追加」(`add_league_entry_slot`)、「+1枠を移す」(`move_empty_league_entry_slot`)、割り当て解除時の枠削除(`unassign_league_entry_participant`)、ペア割り付けの画面の表示条件(`core/views/league.py`)が、これを使っている。
   - そのため、途中のグループを+1にすると、どのグループが+1かを取り違える。Stage枠CSVで途中のグループを多くして読み込んだ場合も、今すでに同じ取り違えが起きうる。
   - 対策: Stage作成時(画面・CSV)に、各グループの本来の組数を記録する(Group に項目を1つ足す。マイグレーションが要る)。`group_base_size` は記録があればそれを使い、なければ今の決まりで計算する。
2. **今の「+1枠を追加」は、後ろのグループの番号をずらす。**
   - `_create_empty_league_entry_slot` は、そのグループの最大番号+1の位置に枠を入れ、それより後ろの全グループの番号を1ずつずらす。枠を消すときは逆に詰める(`_delete_league_entry_and_renumber`)。
   - Bの新しい処理は、これとは別の作り方(最後の番号の次を付け、ずらさない)にする。番号がとびとびでも、表示・CSV・進行表が崩れないかを実装前に確かめる。
3. **今の「+1枠を追加」は、試合を作らない。**
   - 総当たり試合を作るのは、Stage作成(`create_league_stage_groups`)、Stage枠CSVの取り込み、カテゴリ詳細画面の「試合を生成」(`generate_group_matches`。今はメニューから入れない画面)だけ。

## 今の「+1枠」機能の位置づけ(要検討)

- [participant_db_design.md](participant_db_design.md) の「リーグの＋1枠D&D機能の位置づけ」(2026-09-20)には、次のように書かれている。
  - 「+1枠」の操作は、結果入力が始まった後の、最後の手段の「裏機能」。
  - 通常は、参加ペア数を変えてStage編集で作り直す。
- ユーザーの認識は「Isconyで一からリーグを作るための機能」だったが、ユーザー自身、認識が違っていたかもしれないと言っている(2026-11-16)。今の機能をどう位置づけるか、残すか・Bに寄せるかは、もう少し検討する。
- 今の画面では、+1は主にD&Dで使う。未割当の参加者を「+1枠を追加」の行へ落とすと、枠ができて割り当てられる。ほかに「別グループへ移動」「枠を解除」がある。

### 不具合: 結果が入ったStageでも、+1の操作で番号がずれていた(2026-11-16 修正に着手)

- +1枠の追加(ボタン・D&D)・別グループへの移動・解除、+1枠の組の「未割当に戻す」は、Stageに結果が入っていても止まらなかった。そのたびに、後ろのグループの番号が1つずつずれていた。
- 進行中のリーグで番号が変わると、画面・速報・公開の進行表・進行表CSVが、紙のリーグ表やプログラムと食い違う。ユーザーと「新しい機能より先に直す致命的な不具合」と判断した。
- 直し方(ユーザーと合意):
  - 結果が入っているリーグStageでは、番号がずれる操作をすべて止める。判定は、Stage編集のロックと同じ `_stage_has_results`。
  - +1枠の組の「未割当に戻す」は、枠を残して参加者だけを外す。
  - 結果が1つも入っていないStageは、今までどおり操作できる。判断はStageごと。
